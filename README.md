## 1. Призначення та функціональні можливості

Вебсистема призначена для автоматизації обліку фізичних одиниць прокатного обладнання за інвентарними номерами, візуалізації їхньої зайнятості на часовій шкалі з урахуванням обов'язкової технічної перерви на обслуговування між видачами, точного розрахунку вартості оренди та застави в цілих копійках, оформлення бронювань із захистом від подвійного резервування, ведення черги очікування (`Waitlist`) та обліку фактичної видачі й повернення із нарахуванням пені за прострочення.

### Основні можливості за ролями
1. **Гість (неавтентифікований користувач):**
   - перегляд каталогу позицій обладнання та фізичних інвентарних екземплярів (`INV-GEN-001`..`INV-LCA-002`);
   - пошук за назвою, моделлю або інвентарним кодом, фільтрація за категорією та бажаним часовим вікном доступності;
   - перегляд інтерактивної матриці календаря доступності кожного фізичного екземпляра з відображенням активних оренд і буферів технічного обслуговування;
   - попередній розрахунок вартості оренди, суми застави та межі закінчення технічної перерви (`POST /api/availability/preview`).
2. **Клієнт (автентифікований орендар, роль `CLIENT`):**
   - оформлення заявки на оренду конкретного інвентарного екземпляра (`POST /api/bookings`) з атомарною перевіркою перетину інтервалів у транзакції `BEGIN IMMEDIATE`;
   - постановка в чергу очікування (`POST /api/waitlist`) у разі зайнятості екземпляра (`409 Conflict / INTERVAL_CONFLICT`) з автоматичним переведенням у стан `NOTIFIED` після вивільнення вікна;
   - перегляд власних бронювань та історії подій у кабінеті клієнта (`GET /api/bookings`), продовження оренди на новий термін (`POST /api/bookings/{id}/extend`) та скасування власної заявки (`POST /api/bookings/{id}/cancel` з контролем власника ресурсу).
3. **Менеджер прокату (роль `MANAGER`):**
   - перегляд повного реєстру заявок усіх клієнтів та статистики парку обладнання;
   - погодження (`CONFIRMED`) або аргументоване відхилення (`REJECTED`) заявок (`POST /api/bookings/{id}/decision`);
   - реєстрація фактичної видачі обладнання зі складу (`ISSUED`, `POST /api/bookings/{id}/issue`);
   - реєстрація повернення обладнання (`RETURNED`, `POST /api/bookings/{id}/return`) з автоматичним обчисленням прострочених годин і пені за тарифом;
   - переведення фізичних екземплярів між станами `AVAILABLE`, `IN_MAINTENANCE` та `RETIRED` (`PATCH /api/equipment-units/{id}/condition`).

## 2. Архітектура та технологічний стек

Система побудована за клієнт-серверним архетипом із чітким чотиришаровим поділом відповідальності (**Clean / Layered Architecture**):

| Шар / Підсистема | Проєкт / Директорія | Технології та призначення |
|---|---|---|
| **Presentation (SPA)** | `client/` → `wwwroot/` | **React 19.0.0**, **Vite 6.2.0**, адаптивна сітка CSS Grid/Flexbox (360px / 768px / 1280px), семантична розмітка WCAG 2.2 AA |
| **Presentation (HTTP API)** | `src/EquipmentRental.WebApi` | **ASP.NET Core 10.0 Web API (`net10.0`)**, Kestrel, `RentalApiController`, серверні сесії в `HttpOnly` Cookie (`SessionAuthManager`), відповіді про помилки за **RFC 9457 Problem Details** |
| **Application Layer** | `src/EquipmentRental.Application` | `RentalApplicationService`, контракти вхідних і вихідних DTO (`ContractsAndDtos.cs`), мапінг моделей |
| **Domain Layer** | `src/EquipmentRental.Domain` | Чиста предметна логіка без зовнішніх залежностей: сутності, `Money` (точні копійки `long`), `PricingAndAvailabilityRules` (перевірка перетину інтервалів з урахуванням `maintenance_buffer_hours`, тарифний калькулятор, розрахунок пені, автомат станів), контракт `IRentalRepository` |
| **Infrastructure Layer** | `src/EquipmentRental.Infrastructure` | **SQLite 3 (режим WAL)** через `Microsoft.Data.Sqlite 10.0.0`, параметризовані SQL-запити, транзакції `BEGIN IMMEDIATE`, хешування паролів `PBKDF2-SHA256` (`PasswordHasher`) |
| **Automated QA & Benchmarks** | `tests/EquipmentRental.Tests` | Модульні та інтеграційні тести (`TC-UT-01`..`05`, `TC-IT-01`..`07`), стенд тестування обсягом даних (100 / 1 000 / 10 000 записів) та навантажувального тестування (5 / 10 / 25 одночасних віртуальних користувачів) |

## 4. Швидкий старт та інструкція з розгортання

### 4.1. Системні вимоги
- **.NET SDK 10.0** (або новіший)
- **Node.js 22 LTS** (опційно — лише для перезбирання фронтенду `client/`; скомпільований бандл уже включено до `src/EquipmentRental.WebApi/wwwroot/`)
- **СКБД SQLite 3** (вбудована через пакет `Microsoft.Data.Sqlite 10.0.0`, окремий сервер БД не потрібен)

### 4.2. Збирання та запуск застосунку
```powershell
# 1. Клонування або перехід у кореневу теку проєкту
cd Coursework_Var12_EquipmentRental

# 2. Компіляція рішення .NET
dotnet build EquipmentRental.sln

# 3. Запуск вебсервера (автоматично ініціалізує sql/init.sql та sql/seed.sql)
dotnet run --project src/EquipmentRental.WebApi/EquipmentRental.WebApi.csproj --urls http://localhost:5080
```
Після запуску відкрийте у браузері адресу **http://localhost:5080**.

### 4.3. Запуск автоматизованих тестів і стенда продуктивності
```powershell
dotnet run --project tests/EquipmentRental.Tests/EquipmentRental.Tests.csproj
```
Команда виконує 12 автоматизованих тест-кейсів (`TC-UT-01`..`05`, `TC-IT-01`..`07`), експеримент з обсягом даних (`100`, `1 000`, `10 000` записів у `bookings` із порівнянням часу з індексом `idx_bookings_unit_interval` і без нього) та навантажувальне тестування (`5`, `10`, `25` віртуальних користувачів) і зберігає звіт у `evidence/test_results.json`.
